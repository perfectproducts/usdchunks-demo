The USDChunks examples, and what each one shows

USDChunks keeps a node network of Python "chunks" inside an OpenUSD file. Each chunk is a prim, each wire is a USD connection, and each chunk writes into its own layer. The repository ships eight example scripts that build networks with the Scene API. Each one saves the network and exports the cooked result as plain USD.

Two files per example

*_network.usdaThe recipe: chunk prims, their params and wires. Open it in usdview and the Chunks panel shows the graph and recooks it live. It is small (the biome network is 9 KB).
*.usdaThe cooked result as plain USD, with no usd_chunks needed to read it. The biome result is 2 MB of PointInstancers.
scene.create.<chunk>(upstream, …)Each call adds a chunk node. Passing the previous node wires it in, so the order of the calls is the cook order.
node.get_param("…")Passing a param object instead of a value links two params, so one prim path is set in one place and followed everywhere.

Running them on this machine

usdview comes from NVIDIA's prebuilt OpenUSD 25.08 in C:\usd_root (Python 3.12, with PySide6). usd_chunks runs from the clone, and its Python packages are in a separate deps folder, so C:\usd_root itself is unchanged.

C:\_DEMO\USDChunks\build_examples.bat                  :: re-run all 8 scripts into .\output
C:\_DEMO\USDChunks\usdview_chunks.bat                  :: usdview + Chunks panel (box network)
C:\_DEMO\USDChunks\usdview_chunks.bat output\biome_network.usda

:: CLI, after "call env.bat" in a cmd window

python -m usd_chunks.cli run output\use_groups\groups_network.usda Rocks.Scatter_seed=3 Stairs.Stairs_copies=20 -o out.usda
env.batSets PYTHONPATH (clone + deps), PXR_PLUGINPATH_NAME (the usdview plugin), USD_CHUNK_DIRS (bundled chunks), then calls NVIDIA's set_usd_env.bat.
deps\attrs, typing-extensions, numpy 2, scipy, requests, mujoco, fast-simplification. With these, the Scatter, Mesh, Vine, Poly Reduce and RBD chunks all load.
In usdviewPress Tab or right-click the graph to add chunks. Open a *_network.usda to see a graph, or a plain *.usda to see a result.
Not installedusd_gizmos, the drag handles in the viewport. Its GitHub repo is not public yet. Everything else works without it.
Basics

Wiring, linked params and layers

A coloured box

examples/scripts/box.py

The smallest possible network: three chunks in a row. A good first file to open in usdview, to see how a script turns into a graph.

cube → Mesh transform ty=3 set_display_color (1, .2, .1)
How it uses usdchunks
  • scene.create.cube is an alias for the Mesh chunk with mesh_type='cube'.
  • box.get_param("prim_path") is passed to Transform and Set Display Color, so all three follow the box if it moves.
  • scene.save() writes the network and scene.export() writes the flattened result.

Shot setup in its own layer

examples/scripts/shot_setup.py

A ground, an aimed key light and a camera, all authored into a layer called "shot" instead of the session layer.

layer "shot" edit_target "shot" ground rect_light transform aim camera 35 mm
How it uses usdchunks
  • The Edit Target chunk works as a Python with block. Every chunk created inside it cooks after it, so their edits land in the "shot" layer.
  • It is one straight chain, so the whole thing also cooks in usdview.

Meshes versus USD shapes

examples/scripts/cubes_mesh_or_gprim.py

The same cube and sphere built twice: as polygon meshes from the Mesh chunk, and as USD's own Cube/Sphere gprims from the Shape chunk.

cube Mesh sphere Mesh usd_cube Shape transform usd_sphere Shape transform
How it uses usdchunks
  • Explains when to use which: Mesh gives polygons with UVs you can deform or texture, and Shape gives a parametric prim that the renderer tessellates.
  • Shows the placement difference: the Mesh cube sits on its origin, and the USD Cube is centred on it, hence the ty=0.5 transforms.

Procedural scenes

Scattering, fields and growth

Nested forest biome

examples/scripts/biome.py

The example from the blog post. Four scatter layers are stacked, and each one is placed relative to the layers before it.

mesh grid 80×80 inline_usd protos noise_field "forest" scatter_points Trees scatter_points Bushes scatter_points Ferns scatter_points Grass
How it uses usdchunks
  • Inline USD writes hand-typed .usda prototypes (cones, spheres) straight into the scene.
  • Noise Field paints a forest primvar on the ground, and the trees use it as their density, which leaves clearings.
  • "Grow Near" (near_prims) reads an earlier layer's PointInstancer: bushes under trees, ferns around bushes, and grass away from trees (inverted).
  • Params are set with dotted names for list items, for example prototypes.0.proto_path.

Ivy on a stone wall

examples/scripts/ivy_wall.py

The longest chain of the examples, and ready to render: a painted wall grows vines, the vines are turned into meshes and shaded, then leaves, lights and a camera are added.

ground cube wall preview_surface stone scatter_brush vine curves_to_mesh preview_surface bark inline_usd leaf mesh preview_surface leaf scatter_points leaves light distant transform aim light dome camera
How it uses usdchunks
  • chunk.change_block() batches all the node creation, so the chain cooks once instead of after every node.
  • The script paints the Scatter Brush the way a viewport stroke would (start_gizmo, gizmo.apply_stroke, stop_gizmo). The paint is stored on the brush chunk, so the saved network keeps it.
  • Outputs feed later inputs: the Vine's density_primvar comes from the brush, and the leaves scatter on the Vine's out_leaves points.
  • The leaf prototype is generated in Python (a five-lobed, cupped fan) and added with Inline USD.
  • build(animate=True) grows the vine over frames 1–48.

Pipeline

Department layers and export

A shot split into departments

examples/scripts/shot_departments.py

A shot layered over a set file, with layout, lighting and camera each in a separate layer, then exported as one file per layer. It shows how a network can author a studio's layer structure rather than just geometry.

stage_settings sublayer set.usda layer layoutedit_targettransform MoveBoxedit_target session layer lighting…distant_light Key… layer camera…camera aim_at box… export_usd bake_all
How it uses usdchunks
  • Each department follows the same pattern: Layer, Edit Target into it, its edits, then Edit Target back to the session layer so the next layer sits beside it.
  • Scene.new(path=…) places the network on disk, so relative paths such as ../inputs/set.usda resolve the way they would in USD.
  • Export USD's export_layers rows switch off the set and the network itself. scene.commit() runs the export, the same as usdchunks run.

Reusable assets

ChunkGroups: networks as parameterised assets

A ChunkGroup wraps a network into one file. "Lofting" exposes chosen inner params on the group, so another scene can reference the file and set only those.

Building two groups

examples/groups/build_groups.py
ScatterOnTerrain
chunkgroupscatter_points Scatter
SpiralStairs
chunkgroupusd_cube Steptransform Placeduplicate_prim Stairsprune_prim DropSource
How it uses usdchunks
  • scene.create.chunkgroup(name, doc) used as a with block collects the nodes inside it.
  • chunk_stage.loft_param_to_context exposes inner params as Scatter_density, Stairs_copies, Place_tx and so on.
  • Scene(lazy=True) skips cooking, since a group file has no terrain of its own to scatter on. export_network writes the group file.
  • usdchunks info <file> prints the group's description and its lofted params.

Using the groups

examples/scripts/use_groups.py

Two Reference chunks bring the group files into a scene and set their lofted params, as if each group were a single chunk.

stage_settings sublayer terrain.usda usd_sphere rock reference Rocks reference Stairs
How it uses usdchunks
  • Scatter_density=2.0 on faces within 20° of flat gives exactly 200 rocks on the 10 × 10 m terrain.
  • Stairs_copies=12, with a rise of 0.2 and a turn of −30° per step.
  • You can override params from the command line without editing the file: run groups_network.usda Rocks.Scatter_seed=3 Stairs.Stairs_copies=20 -o out.usda. This was tested here.
Writes, under use_groups/
terrain.usdagroups_network.usdagroups.usda

It warns that the group paths are absolute. That is harmless here, but a shared network should reference them by relative path.

Beyond the eight scripts

The blog post also shows larger demos built from the same chunks: a parametric Swedish house (house chunk), a MaterialX wood shader, a refrigerator articulation posed with pose_articulation, a 196-asset proxy batch (usdchunks batch with Remesh Proxy, UV Unwrap and Bake Textures) and a 222-chunk village. Those scene files are not in the repo, but every chunk they use is in the bundled set, so you can add them in usdview with Tab.
